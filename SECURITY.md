# Безопасность

[Русский](SECURITY.md) | [English](SECURITY.en.md)

## Что нельзя публиковать

Никогда не добавляйте в GitHub:

- `SshTunnelTray.json` и любые рабочие конфигурации;
- приватные SSH-ключи (`id_ed25519`, `id_rsa`, `*.pem`, `*.ppk`, `*.pfx` и подобные файлы);
- пароли, токены, `.env`, файлы credentials и дампы памяти;
- сгенерированные `.cmd`, логи и диагностические дампы;
- скриншоты с реальными адресами серверов, логинами, путями, ключами или содержимым терминала;
- результаты сборки и локальные файлы IDE, которые могут содержать абсолютные пути.

`.gitignore` предотвращает обычное добавление таких файлов, но не является защитой для файла, который уже был добавлен в индекс. Поэтому перед коммитом запускайте:

```powershell
pwsh -NoProfile -File .\scripts\Verify-Public.ps1 -TrackedOnly
```

## Локальные данные приложения

Рабочий JSON может содержать адрес SSH-сервера, логин, путь к приватному ключу, параметры проброса и зашифрованный пароль. Даже зашифрованное значение не следует публиковать: формат и ключ шифрования являются частью исходного приложения, а сам файл содержит метаданные окружения.

В публичном репозитории допустим только обезличенный [пример](samples/SshTunnelTray.json.example) с `example.com`, `your-user` и `YOUR_NAME`.

## Если секрет уже попал в Git

1. Немедленно отзовите или замените соответствующий пароль, ключ или токен. Удаления файла из последнего коммита недостаточно: значение остается в истории.
2. Не публикуйте секрет в issue, pull request или комментарии.
3. Удалите секрет из истории отдельной проверенной процедурой (`git filter-repo` или эквивалент) и проверьте все ветки и tags.
4. Включите на GitHub Secret scanning и push protection.
5. Повторно запустите `Verify-Public.ps1 -TrackedOnly` и проверьте staged diff.

## Сообщение о проблеме

Обычные ошибки можно описывать через issue без конфигураций и логов. О потенциальной утечке не создавайте публичный issue: используйте private vulnerability reporting после включения этой функции в настройках репозитория или свяжитесь с владельцем проекта через его GitHub-профиль.

## Границы защиты

Локальная проверка и GitHub Action блокируют известные опасные имена файлов и распространенные шаблоны секретов. Они не могут надежно определить секрет внутри произвольного изображения или зашифрованного архива, поэтому ручная проверка staged diff обязательна.
